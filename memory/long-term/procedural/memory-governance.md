# Electricity Monitor memory 治理规则

## 适用场景

- 需要在仓库内新增、更新、晋升、归档或删除 memory 文件时。
- 需要判断某条信息应进入长期事实、长期流程、短期工作态、问题记录还是决策记录时。
- 需要重构 memory 入口、目录结构或与 AGENTS 的同步关系时。

## 结构模型

- `memory/README.md` 是全仓唯一全局入口。
- `long-term/semantic/` 只放长期稳定事实。
- `long-term/procedural/` 只放长期稳定流程。
- `short-term/working/current.md` 是短期工作态固定入口；仅在必要时再拆分额外短期文件。
- `issues/` 与 `decisions/` 只在确有长期复用价值时使用，不为了凑结构制造内容。

## 长期与短期边界

- 长期记忆只记录跨会话仍然成立的仓库事实、模块职责、配置真源、测试入口、部署契约、长期风险和协作边界。
- 短期记忆只用于阶段性但需要跨会话延续的事实，例如待验证外部环境、短期兼容窗口或尚未收敛的迁移观察点。
- 不进入长期记忆的内容包括：一次性命令输出、单次报错栈、最近一次通过数、单次审计统计、脏工作树状态、机器私有路径和任何真实凭据原文。

## 短期记忆规则

- 短期文件统一命名为 `st-<slug>.md`。
- 短期文件头必须显式写明：状态、来源、最后校验、失效条件。
- `short-term/working/current.md` 当前仅保留空骨架；后续出现真实跨会话工作态时，再在该入口维护。
- 已稳定的短期事项要并入长期文件；已失效的短期事项要直接删除或标记退出活动入口。

## 问题记录与决策记录

- `issues/` 只收录真正值得复用的问题资产，至少应回答现象、影响范围、根因、定位方式、修复方式和预防措施。
- `decisions/` 记录影响协作边界、运行时契约、长期工作流或工具链真源的稳定决策，并回链到对应长期文件。
- 问题或决策若改变了长期事实或长期流程，必须同步修正对应长期文件与 `memory/README.md`。

## 更新与收口

1. 先让代码、脚本、CI 和文档真源成立，再把稳定结论写回 memory。
2. 优先更新现有权威文件，不盲目新增平行真相源。
3. 调整 memory 结构、目录职责或入口文件时，同时更新 `memory/README.md` 与相关 `AGENTS.md`。
4. 修改后至少做路径、引用、frontmatter 和真源一致性自检。
