# Electricity Monitor memory 规则

## 长期记忆

- 长期记忆只记录跨会话仍然成立的仓库事实、模块职责、配置真源、测试入口、部署契约、长期风险和协作边界。
- 长期记忆必须可验证，且应直接服务后续任务，而不是复述一次性工作过程。
- 长期记忆变更后，应优先让对应代码、脚本、CI 和文档真源保持一致，再写回 memory。

## 短期记忆

- 短期记忆只在确有必要时创建，且必须放在对应主题目录下，不额外建立独立短期专区。
- 短期文件统一命名为 `st-<slug>.md`。
- 每个短期文件头必须显式写明：
  - `状态`
  - `来源`
  - `最后校验`
  - `失效条件`
- 短期记忆只用于阶段性但需要跨会话延续的事实，例如待验证外部环境、短期兼容窗口或尚未收敛的迁移观察点。

## 明确不进入 memory 的内容

- 本地调试日志、单次报错栈、一次性命令输出。
- 最近一次测试通过数、单次审计统计或脏工作树状态。
- 机器私有环境、local environment路径差异和任何真实凭据原文。
- 已经失效的迁移阶段说明、历史进度口号或无复用价值的过程噪音。

## 更新准则

- 新写入内容必须能从代码、配置、CI、脚本或当前文档真源验证。
- 已经稳定的短期事项要并入长期文件；已经失效的短期事项要直接删除。
- 若结构调整导致目录职责、入口文件或 AGENTS 拓扑变化，应同步更新 `memory/README.md`、`01-governance/02-repo-shape-and-agents.md` 和相关 `AGENTS.md`。
